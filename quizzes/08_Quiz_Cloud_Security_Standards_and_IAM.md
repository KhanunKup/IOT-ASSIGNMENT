### ข้อที่ 1
ตามเอกสาร **NIST SP 800-145 (The NIST Definition of Cloud Computing)** คุณลักษณะสำคัญ 5 ประการ (5 Essential Characteristics) ของคลาวด์คอมพิวติงประกอบด้วยข้อใดบ้าง?
A. Speed, Memory, Storage, Backup, Antivirus  
B. On-demand self-service, Broad network access, Resource pooling, Rapid elasticity, และ Measured service  
C. SaaS, PaaS, IaaS, Public, Private  
D. Virtualization, Container, Kubernetes, Docker, Linux  
**เฉลย: B**  
**คำอธิบาย:** NIST SP 800-145 กำหนด 5 คุณลักษณะจำเป็นของ Cloud Computing ไว้ดังนี้:
1. On-demand self-service (ให้บริการตนเองตามความต้องการ)
2. Broad network access (เข้าถึงได้ผ่านเครือข่ายกว้างขวาง)
3. Resource pooling (การใช้ทรัพยากรร่วมกัน)
4. Rapid elasticity (ความยืดหยุ่นปรับขนาดได้อย่างรวดเร็ว)
5. Measured service (การคิดค่าบริการตามปริมาณที่ใช้งานจริง)

### ข้อที่ 2
มาตรฐานสากล **ISO/IEC 27017** และ **ISO/IEC 27018** มีขอบเขตการกำกับดูแลด้านความมั่นคงปลอดภัยบนคลาวด์ที่แตกต่างกันอย่างไร?
A. ISO 27017 สำหรับระบบเครือข่าย ส่วน ISO 27018 สำหรับการเขียนโปรแกรม  
B. ISO/IEC 27017 มุ่งเน้นการควบคุมความมั่นคงปลอดภัยสารสนเทศสำหรับบริการคลาวด์ (Cloud Security Controls) ในขณะที่ ISO/IEC 27018 มุ่งเน้นการคุ้มครองข้อมูลส่วนบุคคล (Protection of Personally Identifiable Information - PII) บนบริการพับลิกคลาวด์โดยเฉพาะ  
C. ISO 27017 เป็นมาตรฐานสำหรับฮาร์ดแวร์ ส่วน ISO 27018 เป็นมาตรฐานสำหรับระบบปฏิบัติการ  
D. ทั้งสองมาตรฐานถูกยกเลิกไปแล้ว  
**เฉลย: B**  
**คำอธิบาย:** 
- **ISO/IEC 27017:** เป็นแนวทางปฏิบัติสำหรับ Cloud Service Controls (ต่อยอดจาก ISO 27002) ทั้งฝั่งผู้ให้บริการและผู้ใช้บริการ
- **ISO/IEC 27018:** เจาะจงด้านความเป็นส่วนตัวและการคุ้มครองข้อมูล PII ใน Public Cloud สอดคล้องกับกฎหมายคุ้มครองข้อมูลส่วนบุคคล

### ข้อที่ 7
ตามแนวทาง **NIST SP 800-63 (Digital Identity Guidelines)** การประเมินระดับความเชื่อมั่นในอัตลักษณ์ดิจิทัลแบ่งออกเป็น 3 มิติ (Levels of Assurance) ข้อใดจับคู่ตัวย่อได้ถูกต้อง?
A. CIA, AAA, IAM  
B. IAL (Identity Assurance Level), AAL (Authenticator Assurance Level), และ FAL (Federation Assurance Level)  
C. SSL, TLS, VPN  
D. CPU, RAM, ROM  
**เฉลย: B**  
**คำอธิบาย:** NIST SP 800-63 แบ่งความเชื่อมั่นออกเป็น 3 ด้าน:
- **IAL:** ความเชื่อมั่นในการพิสูจน์ยืนยันตัวตนบุคคลตอนลงทะเบียน (Identity Proofing)
- **AAL:** ความเชื่อมั่นของอุปกรณ์และกลไกที่ใช้ล็อกอิน (Authentication & Tokens)
- **FAL:** ความเชื่อมั่นในกระบวนการส่งต่ออัตลักษณ์ข้ามระบบ (Federation Assertions)

### ข้อที่ 8
ความแตกต่างที่สำคัญที่สุดระหว่างกระบวนการ **Authentication (การพิสูจน์ตัวตน)** และ **Authorization (การกำหนดสิทธิ์)** คือข้อใด?
A. Authentication ถามว่า "คุณมีเงินเท่าไร?" ส่วน Authorization ถามว่า "คุณชื่ออะไร?"  
B. Authentication เป็นการตรวจสอบและยืนยันว่า "คุณคือใครจริงหรือไม่?" (Who you are) ในขณะที่ Authorization เป็นการตรวจสอบว่า "คุณมีสิทธิ์ทำสิ่งนั้นหรือไม่?" (What you are allowed to do)  
C. ทั้งสองคำมีความหมายเหมือนกันทุกประการ  
D. Authorization ต้องทำก่อน Authentication เสมอ  
**เฉลย: B**  
**คำอธิบาย:** 
- **Authentication:** พิสูจน์ความจริงของตัวตนผู้ใช้ (เช่น ตรวจรหัสผ่าน, สแกนนิ้ว)
- **Authorization:** ตรวจสอบนโยบายและสิทธิ์ในการเข้าถึงทรัพยากร (เช่น อ่านไฟล์นี้ได้หรือไม่) หลังผ่านการพิสูจน์ตัวตนแล้ว

### ข้อที่ 9
รูปแบบการควบคุมการเข้าถึงแบบ **Role-Based Access Control (RBAC)** มีหลักการทำงานอย่างไร?
A. กำหนดสิทธิ์ให้ผู้ใช้แต่ละคนเป็นรายบุคคลโดยตรงตามใจผู้สร้างไฟล์  
B. กำหนดสิทธิ์การเข้าถึงทรัพยากรให้แก่ "บทบาทหน้าที่ (Roles)" ภายในองค์กร จากนั้นจึงกำหนดผู้ใช้งาน (Users) ให้สังกัดในบทบาทหน้าที่นั้นๆ  
C. กำหนดสิทธิ์ตามระดับชั้นความลับของรัฐบาล (Top Secret / Secret)  
D. สุ่มสิทธิ์ใหม่ทุกครั้งที่เปิดเครื่อง  
**เฉลย: B**  
**คำอธิบาย:** RBAC ช่วยลดภาระการบริหารจัดการสิทธิ์ โดยผูกสิทธิ์ (Permissions) ไว้กับ Role (เช่น Role: Accountant, HR Manager) เมื่อมีพนักงานใหม่ เพียงแค่ใส่พนักงานคนนั้นลงใน Role ที่สอดคล้อง

A. ABAC ไม่ต้องใช้เซิร์ฟเวอร์ในการประมวลผล

### ข้อที่ 13
เทคโนโลยี **OpenID Connect (OIDC)** มีความสัมพันธ์กับ **OAuth 2.0** อย่างไร?
A. เป็นเทคโนโลยีที่เป็นคู่แข่งและไม่สามารถทำงานร่วมกันได้  
B. OpenID Connect เป็นส่วนขยายเลเยอร์การพิสูจน์ตัวตน (Authentication Layer) ที่ถูกสร้างต่อยอดอยู่บนพื้นฐานของ OAuth 2.0 โดยมีการเพิ่ม **ID Token** ในรูปแบบ JSON Web Token (JWT) เพื่อส่งข้อมูลตัวตนของผู้ใช้  
C. OpenID Connect ใช้สำหรับส่งอีเมลขยะ  
D. OAuth 2.0 ถูกสร้างทับบน OpenID Connect  
**เฉลย: B**  
**คำอธิบาย:** OIDC = Identity layer on top of OAuth 2.0 โดย OAuth 2.0 ให้ Access Token สำหรับ Authorization ส่วน OIDC เพิ่ม ID Token (JWT) เพื่อส่งข้อมูล Profile และ Identity ของผู้ใช้ (Authentication)

### ข้อที่ 15
พิจารณาตัวอย่างคำสั่งนโยบาย IAM Policy ด้านล่าง:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-company-backup/*"
    }
  ]
}
```
คำสั่งในบล็อก `"Effect": "Allow"` และ `"Action": "s3:GetObject"` นี้มีความหมายว่าอย่างไร?
A. อนุญาตให้ลบ Bucket ชื่อ `my-company-backup` ได้  
B. อนุญาตให้ดาวน์โหลดหรืออ่านไฟล์ข้อมูล (Get Object) จากทุกอ็อบเจกต์ที่อยู่ภายใน S3 Bucket ที่ชื่อ `my-company-backup`  
C. ปฏิเสธการเข้าถึง S3 ทั้งหมด  
D. เปลี่ยนรหัสผ่านของระบบจัดเก็บข้อมูล S3  
**เฉลย: B**  
**คำอธิบาย:** Action `s3:GetObject` คือสิทธิ์ในการอ่าน/ดาวน์โหลดไฟล์จาก S3 และเครื่องหมาย `/*` ที่ Resource หมายถึงอนุญาตทุกไฟล์ภายในบักเก็ตดังกล่าว

### ข้อที่ 16
ในเอกสารนโยบาย IAM Policy รูปแบบมาตรฐานของสตริงระบุทรัพยากร (Resource Identifier) เช่น:
`"arn:aws:s3:::my-company-backup/*"`
ตัวย่อ **ARN** ย่อมาจากคำว่าอะไร?
A. Advanced Routing Node  
B. Amazon Resource Name  
C. Automated Rule Network  
D. Application Reference Number  
**เฉลย: B**  
**คำอธิบาย:** ARN ย่อมาจาก **Amazon Resource Name** เป็นรูปแบบไวยากรณ์สากลที่ใช้ระบุชื่อและตำแหน่งของทรัพยากรแต่ละชิ้นบน AWS อย่างไม่ซ้ำกันทั่วโลก

### ข้อที่ 17
หากในระบบ IAM Policy มีนโยบายสองข้อขัดแย้งกัน โดยข้อหนึ่งระบุ `"Effect": "Allow"` และอีกข้อหนึ่งระบุ `"Effect": "Deny"` ไปยัง Resource ตัวเดียวกัน ตามกฎสากลของ Cloud IAM นโยบายใดจะได้รับสิทธิ์เด็ดขาดในการบังคับใช้ (Evaluation Logic)?
A. Allow ชนะเสมอ  
B. Explicit Deny ชนะเสมอ (หากมีกฎสั่ง Deny แม้แต่ข้อเดียว การเข้าถึงจะถูกปฏิเสธทันที)  
C. กฎข้อที่เขียนล่าสุดจะชนะ  
D. ระบบจะสุ่มเลือก  
**เฉลย: B**  
**คำอธิบาย:** กฎการประเมินสิทธิ์ IAM บนระบบคลาวด์ยึดหลัก:
1. Default Deny (เริ่มต้นไม่มีสิทธิ์)
2. มี Allow กฎจึงจะเปิดทางให้เข้าถึงได้
3. **Explicit Deny overrides Allow** เสมอ หากมีข้อสั่ง Deny แม้แต่ข้อเดียว จะถูกปฏิเสธทันทีโดยไม่มีข้อยกเว้น

### ข้อที่ 18
หลักการกำหนดสิทธิ์การเข้าถึงข้อมูลที่สำคัญที่สุดในระบบ IAM คือ **Principle of Least Privilege** ข้อใดอธิบายหลักการนี้ได้ถูกต้อง?
A. ให้สิทธิ์ระดับ Administrator แก่พนักงานทุกคนเพื่อความสะดวกรวดเร็วในการทำงาน  
B. การกำหนดสิทธิ์ให้ผู้ใช้งาน โปรแกรม หรือเซอร์วิส มีสิทธิ์เข้าถึงเฉพาะทรัพยากรและคำสั่งที่จำเป็นต้องใช้ในการปฏิบัติงานตามหน้าที่เท่านั้น ไม่ให้เกินความจำเป็น  
C. การไม่ให้สิทธิ์ใครเลยแม้กระทั่งผู้ดูแลระบบ  
D. การเปลี่ยนรหัสผ่านทุกๆ 1 ชั่วโมง  
**เฉลย: B**  
**คำอธิบาย:** หลักการ Least Privilege ระบุว่าผู้ใช้หรือโปรเซสควรได้รับสิทธิ์ในระดับต่ำที่สุดเท่าที่เพียงพอต่อการปฏิบัติหน้าที่ให้ลุล่วง เพื่อจำกัดขอบเขตความเสียหาย (Blast Radius) หากบัญชีนั้นถูกแฮกหรือถูกขโมยสิทธิ์
