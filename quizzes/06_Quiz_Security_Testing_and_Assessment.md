# ชุดข้อสอบบทที่ 6: Information Security Testing and Assessment
**อ้างอิงเนื้อหา:** NIST SP 800-115 (Technical Guide to Information Security Testing and Assessment) & Week 12/14 Lecture

---

### ข้อที่ 1
ตามมาตรฐาน **NIST SP 800-115** วงจรระเบียบวิธีในการประเมินความมั่นคงปลอดภัย (Information Security Assessment Methodology) แบ่งออกเป็น 3 ขั้นตอนหลักตามข้อใด?
A. Initial, Middle, Final  
B. Planning, Execution, และ Post-Execution  
C. Scanning, Exploitation, Reporting  
D. Policy, Implementation, Audit  
**เฉลย: B**  
**คำอธิบาย:** NIST SP 800-115 กำหนดขั้นตอนการประเมินความมั่นคงปลอดภัยออกเป็น 3 เฟสหลัก:
1. **Planning Phase:** การวางแผน กำหนดขอบเขต และจัดทำข้อตกลง
2. **Execution Phase:** การลงมือทดสอบ ระบุช่องโหว่ และยืนยันความถูกต้อง
3. **Post-Execution Phase:** การวิเคราะห์สาเหตุที่แท้จริง (RCA), ทำรายงาน และล้างข้อมูลทดสอบ

### ข้อที่ 2
เทคนิคการประเมินในกลุ่ม **Review Techniques** ตาม NIST SP 800-115 มุ่งเน้นการกระทำในลักษณะใด?
A. การส่งแพ็กเก็ตจำลองการโจมตีเพื่อทำให้เซิร์ฟเวอร์ค้าง  
B. การตรวจสอบเอกสาร นโยบาย ค่าคอนฟิกูเรชันของระบบ (System Configuration) ล็อกไฟล์ (Log Review) และชุดกฎระเบียบ (Ruleset Review) โดยไม่ส่งแพ็กเก็ตทดสอบการโจมตีจริง  
C. การแอบดักจับรหัสผ่าน Wi-Fi ของพนักงาน  
D. การเจาะเข้าระบบฐานข้อมูลเพื่อดาวน์โหลดข้อมูลบัตรเครดิต  
**เฉลย: B**  
**คำอธิบาย:** Review Techniques เป็นการตรวจสอบเชิงรับ (Passive Examination) มุ่งเน้นการตรวจเอกสาร, บันทึกการทำงาน (Logs), การตั้งค่าคอนฟิกของระบบ และกฎเกณฑ์ (Firewall/Router Rulesets) เพื่อหาจุดบกพร่องตามมาตรฐาน

### ข้อที่ 3
เทคนิคใดต่อไปนี้จัดอยู่ในกลุ่ม **Target Identification and Analysis Techniques** ตามมาตรฐาน NIST SP 800-115?
A. Documentation Review  
B. Network Discovery, Network Port and Service Identification, และ Vulnerability Scanning  
C. Social Engineering  
D. Password Cracking  
**เฉลย: B**  
**คำอธิบาย:** Target Identification and Analysis คือการค้นหาและระบุเป้าหมาย เช่น Network Discovery (ค้นหาโฮสต์), Port and Service Identification (ค้นหาพอร์ตและเซอร์วิส), Vulnerability Scanning (สแกนหาช่องโหว่), และ Wireless Scanning

### ข้อที่ 4
เทคนิคใดต่อไปนี้จัดอยู่ในกลุ่ม **Target Vulnerability Validation Techniques** ซึ่งเป็นการพิสูจน์ยืนยันว่าช่องโหว่ที่ตรวจพบสามารถถูกนำไปใช้ประโยชน์ในการเจาะระบบได้จริงหรือไม่?
A. Penetration Testing, Password Cracking, และ Social Engineering  
B. Ruleset Review  
C. Network Sniffing  
D. Log Analysis  
**เฉลย: A**  
**คำอธิบาย:** Target Vulnerability Validation Techniques เป็นการยืนยันว่าช่องโหว่มีจริงและใช้ประโยชน์ได้ (Exploitable) ประกอบด้วย 3 เทคนิคหลักคือ: 1. Password Cracking, 2. Penetration Testing (การทดสอบเจาะระบบ), และ 3. Social Engineering

### ข้อที่ 5
การทดสอบเจาะระบบแบบ **Black Box Testing** มีคุณลักษณะที่เด่นชัดอย่างไร?
A. ผู้ทดสอบได้รับแบบแปลนสถาปัตยกรรมเครือข่ายและซอร์สโค้ดของแอปพลิเคชันล่วงหน้าอย่างละเอียด  
B. ผู้ทดสอบไม่มีข้อมูลหรือความรู้ภายในเกี่ยวกับระบบเป้าหมายล่วงหน้าเลย (Zero Knowledge) เพื่อจำลองสถานการณ์เหมือนการโจมตีจากแฮกเกอร์ภายนอกองค์กรอย่างแท้จริง  
C. ผู้ทดสอบได้รับบัญชีผู้ดูแลระบบระดับ Root หรือ Domain Admin ตั้งแต่วันแรก  
D. ผู้ทดสอบทำการทดสอบเฉพาะในห้องมืดเท่านั้น  
**เฉลย: B**  
**คำอธิบาย:** 
- **Black Box:** ผู้ทดสอบไม่มีข้อมูลภายในใดๆ (จำลองแฮกเกอร์ภายนอก)
- **White Box (Clear Box):** ผู้ทดสอบมีข้อมูลครบถ้วน ซอร์สโค้ด ผังระบบ และสิทธิ์เต็มที่
- **Gray Box:** ผู้ทดสอบมีข้อมูลบางส่วน (จำลองพนักงานภายในหรือผู้ใช้ทั่วไป)

### ข้อที่ 6
การทดสอบแบบ **White Box Testing** (หรือ Clear Box Testing) มีประโยชน์ที่เหนือกว่า Black Box อย่างไรในแง่ของความคุ้มค่าและความครอบคลุม?
A. ไม่ต้องขออนุญาตผู้บริหารระดับสูง  
B. ช่วยประหยัดเวลาในการค้นหาข้อมูลเบื้องต้น และสามารถตรวจสอบเจาะลึกไปยังจุดเสี่ยง ซอร์สโค้ด หรือสถาปัตยกรรมภายในที่การสแกนจากภายนอกเข้าไม่ถึงได้อย่างทั่วถึง  
C. ไม่ทิ้งร่องรอยใน Log ของระบบ  
D. ทำการทดสอบได้โดยไม่ต้องใช้อินเทอร์เน็ต  
**เฉลย: B**  
**คำอธิบาย:** White Box ช่วยให้ผู้ประเมินสามารถเข้าถึงข้อมูลเชิงลึก การออกแบบ และคอนฟิกโดยตรง ทำให้ตรวจพบช่องโหว่ที่ซ่อนลึกใน Logic หรือ Source Code ซึ่งการสแกน Black Box แบบสุ่มอาจมองข้ามไป

### ข้อที่ 7
เอกสาร **Rules of Engagement (ROE)** ในการทดสอบเจาะระบบ (Penetration Testing) มีความสำคัญสูงสุดในเรื่องใด?
A. เป็นคู่มือการติดตั้งโปรแกรม Kali Linux  
B. เป็นข้อตกลงอย่างเป็นทางการที่กำหนดขอบเขต (Scope), วันเวลาที่อนุญาต, ระบบที่ห้ามทดสอบ, เทคนิคที่อนุญาตและไม่อนุญาต, รายชื่อผู้ติดต่อฉุกเฉิน, และการคุ้มครองทางกฎหมายเพื่อป้องกันความเสียหายต่อธุรกิจ  
C. เป็นสคริปต์อัตโนมัติสำหรับการรัน Nmap  
D. เป็นใบเสร็จรับเงินสำหรับค่าจ้างผู้ทดสอบ  
**เฉลย: B**  
**คำอธิบาย:** ROE (Rules of Engagement) คือสัญญาและกรอบข้อตกลงร่วมกันระหว่างทีมผู้ทดสอบและผู้ว่าจ้าง เพื่อระบุเป้าหมายที่อนุญาต (In-Scope), สิ่งที่ห้ามแตะต้อง (Out-of-Scope), ขอบเขตความเสียหายที่ยอมรับได้ และแนวทางประสานงานเมื่อเกิดเหตุฉุกเฉิน

### ข้อที่ 8
ในส่วนประกอบของเทมเพลต **ROE** หมวด **Logistics & Personnel** จะต้องระบุข้อมูลสำคัญข้อใดตามสไลด์การบรรยาย?
A. ยี่ห้อของแล็ปท็อปที่ทีมทดสอบนำมาใช้งาน  
B. รายชื่อและข้อมูลติดต่อ (Points of Contact) ของทีมทดสอบ, ผู้บริหารองค์กร และทีม Incident Response รวมถึงขั้นตอน Escalation ในกรณีที่เกิดเหตุระบบล่ม  
C. รหัสผ่าน Facebook ของผู้ดูแลระบบ

### ข้อที่ 9
ในขั้นตอนการวางแผนการทดสอบ (Planning Phase) เหตุใดจึงต้องกำหนดเรื่อง **Legal and Policy Considerations** ไว้อย่างชัดเจน?
A. เพื่อหลีกเลี่ยงการจ่ายภาษีมูลค่าเพิ่ม  
B. เพื่อให้มั่นใจว่ากิจกรรมการทดสอบได้รับความยินยอมเป็นลายลักษณ์อักษรจากเจ้าของระบบอย่างถูกต้องตามกฎหมาย และไม่ละเมิด พ.ร.บ. ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ หรือกฎหมายคุ้มครองข้อมูลส่วนบุคคล (PDPA/GDPR)  
C. เพื่อให้สามารถเผยแพร่รหัสผ่านลงบนอินเทอร์เน็ตได้

### ข้อที่ 10
การวิเคราะห์หาสาเหตุที่แท้จริง หรือ **Root Cause Analysis (RCA)** ในขั้นตอน Post-Execution มีเป้าหมายสำคัญอย่างไรต่อองค์กร?
A. เพื่อหาตัวบุคคลผู้ทำผิดและลงโทษทางวินัย  
B. เพื่อระบุต้นตอของปัญหาในระดับกระบวนการหรือนโยบาย (เช่น ขาดนโยบาย Patch Management หรือขาดการอบรม Secure Coding) มากกว่าการแก้ปัญหาเฉพาะหน้าแบบรายจุด เพื่อยกระดับความปลอดภัยในระยะยาว  
C. เพื่อส่งข้อมูลช่องโหว่ไปยังกลุ่มแฮกเกอร์  
D. เพื่อลดจำนวนพนักงานฝ่ายไอทีลง  
**เฉลย: B**  
**คำอธิบาย:** RCA มุ่งเน้นการตอบคำถามว่า "ทำไมช่องโหว่นี้จึงเกิดขึ้นตั้งแต่แรก?" การพบว่าเซิร์ฟเวอร์ไม่ได้อัปเดตแพตช์ (อาการ) อาจมี Root Cause มาจากการขาดขั้นตอน Patch Verification Policy ระดับองค์กร

### ข้อที่ 11
เมื่อทีมทดสอบค้นพบช่องโหว่ร้ายแรงระดับ **Critical Vulnerability** ที่ส่งผลให้ระบบงานหลักหยุดชะงัก หรือข้อมูลรั่วไหลได้ทันทีในระหว่างขั้นตอน Execution ทีมงานควรปฏิบัติตามแนวทางใดตาม NIST SP 800-115?
A. เก็บเป็นความลับไว้จนกว่าจะส่งรายงานฉบับสมบูรณ์ในอีก 1 เดือนข้างหน้า  
B. แจ้งเตือนผู้ประสานงานหลัก (Point of Contact) หรือทีม Incident Response ขององค์กรทันที (Emergency Escalation) เพื่อดำเนินการบรรเทาความเสียหายฉุกเฉิน  
C. โพสต์ช่องโหว่ลงสื่อสังคมออนไลน์  
D. ทำการเจาะต่อเพื่อขโมยข้อมูลให้ได้มากที่สุด  
**เฉลย: B**  
**คำอธิบาย:** ตามมาตรฐานสากล หากพบช่องโหว่ระดับ Critical/Zero-day หรือพบร่องรอยว่าระบบกำลังถูกแฮกเกอร์จริงฝังตัวอยู่ ทีมทดสอบต้องหยุดและแจ้งผู้มีอำนาจขององค์กรทันทีตามช่องทางฉุกเฉินที่กำหนดใน ROE

### ข้อที่ 12
ในขั้นตอน **Post-Testing Activities** กิจกรรมใดที่ต้องกระทำเพื่อความปลอดภัยของข้อมูลลูกค้าตามข้อกำหนดด้านการจัดการข้อมูลทางเทคนิค (Technical Data Handling)?
A. สำเนาข้อมูลรหัสผ่านที่ดักจับได้เก็บไว้ในแฟลชไดรฟ์ส่วนตัว  
B. การทำลายหรือล้างข้อมูลความลับและหลักฐานทางเทคนิค (Data Sanitization & Destruction) ที่รวบรวมมาระหว่างการทดสอบอย่างปลอดภัย หลังเสร็จสิ้นการส่งมอบงาน  
C. แจกจ่ายไฟล์ดาต้าเบสให้พนักงานคนอื่นศึกษา  
D. อัปโหลดข้อมูลขึ้นเว็บบอร์ดสาธารณะ  
**เฉลย: B**  
**คำอธิบาย:** ข้อมูลที่ได้จากการทดสอบ (เช่น hashes, dumps, รายชื่อพนักงาน) เป็นข้อมูลละเอียดอ่อนสูง เมื่อสรุปผลและส่งมอบงานเรียบร้อย ทีมทดสอบต้องทำลายข้อมูลออกจากอุปกรณ์ทดสอบตามมาตรฐาน Data Destruction

### ข้อที่ 16
การทำ **Ruleset Review** ตามคำแนะนำของ NIST SP 800-115 ช่วยป้องกันข้อผิดพลาดประเภทใดในอุปกรณ์ Firewall หรือ Router?
A. อุปกรณ์ไฟร์วอลล์ไฟดับ  
B. กฎที่ซ้ำซ้อน (Redundant Rules), กฎที่ขัดแย้งกัน (Conflicting Rules), กฎที่เปิดกว้างเกินไป (Overly Permissive Rules) เช่น `permit any any` และกฎเก่าที่เลิกใช้งานแล้ว  
C. การเสื่อมสภาพของสายแลน  
D. ความร้อนสะสมในตู้ Rack  
**เฉลย: B**  
**คำอธิบาย:** Ruleset Review มุ่งตรวจทานโครงสร้างกฎในอุปกรณ์เน็ตเวิร์ก เพื่อค้นหากฎที่ขัดแย้งกัน ลำดับกฎที่วางผิดพลาด กฎที่ไม่มีคนใช้ หรือกฎ Any-Any ที่ผู้ดูแลระบบแอบเปิดทิ้งไว้ชั่วคราวแล้วลืมปิด

### ข้อที่ 17
ความแตกต่างระหว่าง **Vulnerability Assessment (VA)** และ **Penetration Testing (Pentest)** คือข้อใด?
A. VA มีราคาแพงกว่า Pentest เสมอ  
B. VA มุ่งเน้นการตรวจหาและระบุรายชื่อช่องโหว่ทั้งหมดที่อาจมีในระบบ (กว้างแต่ไม่ลึก) ในขณะที่ Pentest จะมุ่งเน้นการจำลองเจาะระบบจริงผ่านช่องโหว่นั้น เพื่อพิสูจน์ผลกระทบและการเข้าถึงข้อมูล (เจาะลึกและยืนยันผลได้จริง)  
C. Pentest ไม่ต้องใช้คอมพิวเตอร์ในการทดสอบ  
D. VA ต้องใช้แฮกเกอร์สายมืดเท่านั้น  
**เฉลย: B**  
**คำอธิบาย:** Vulnerability Assessment (VA) เน้นการทำ Inventory รายการช่องโหว่ทั้งหมดโดยไม่เจาะทำลาย ส่วน Penetration Testing (Pentest) จะนำช่องโหว่เหล่านั้นมาสร้าง Exploit เพื่อเจาะทะลุผ่านระบบป้องกันและประเมินความเสียหายจริง

### ข้อที่ 18
ในการทำ **Log Review** ข้อมูลใดใน Log ที่เป็นหลักฐานสำคัญที่สุดในการนำมาวิเคราะห์เหตุการณ์ย้อนหลัง (Correlation & Timeline Analysis)?
A. ความยาวของข้อความในไฟล์  
B. การบันทึกเวลาที่แม่นยำ (Accurate Timestamp ที่ Sync ตรงกับ NTP Server), Source/Destination IP และ Event ID  
C. ขนาดความจุของฮาร์ดดิสก์  
D. ชื่อเครื่องคอมพิวเตอร์ของผู้ประเมิน  
**เฉลย: B**  
**คำอธิบาย:** Timestamp ที่เที่ยงตรง (ผ่าน Network Time Protocol - NTP) ร่วมกับข้อมูล IP และรายละเอียดกิจกรรม ถือเป็นหัวใจในการทำ Digital Forensics และ Incident Investigation เพื่อนำข้อมูลจากโฮสต์ต่างๆ มาเรียงต่อเป็นลำดับเหตุการณ์จริง (Timeline)
